# 0.1.0-alpha.6 검증 기록 / Validation record

## 한국어

이 문서는 **패키지 생성 전 소스와 관측 기록**입니다. 배포 상태·최종 ZIP 해시·설치 후 검증은 [해당 버전 릴리스](https://github.com/mk0000001/luma-player/releases/tag/v0.1.0-alpha.6)의 첨부 검증 보고서를 기준으로 확인합니다. 현재 소스의 앱 CTest **21/21**, 정상 ASR 네이티브 CPU 검사 **7/7**, PowerShell 7·5.1 인코더 설치 fixture 각각 **25/25**, 실물 UI 복구·동의 회귀 **14/14**, 번역 단위 **80/80**·서비스 **27/27**을 통과했습니다. 실제 CUDA 번역의 직접 작성한 무문맥·문맥 입력 검사도 각각 통과했습니다. candidate2 패키지·CI 검증은 대기 중입니다.

- 고정 Kotoba Q5용 C++ FP16 인코더 변환, 원본·IR 정체성 확인, 실제 호출 수·시간 계측과 별도 NPU 캐시 준비를 구현했습니다. 설치기는 소유 합성 16초 입력으로 실제 요청 4회를 보내고, 실제 NPU·양수인 원시 호출 수를 확인하며 후속 3회 각각의 전체 추론과 벽시계 시간이 모두 3,000ms 이하일 때만 자동 NPU에 적합하다고 판정합니다. 원본·IR·worker·runtime·드라이버에 맞는 calibration이 없거나 검사가 실패하면 GPU를 사용합니다. 광고 TOPS나 아키텍처로 선택하지 않습니다. 기존 base 모델과 명시적 NPU 수동 선택은 유지합니다. 최종 포터블의 설치 profile·GUI 10/60초 버퍼 검증은 대기 중입니다. [설치 안내](../INSTALL-KOTOBA-NPU.md), [성능 기록](../PERFORMANCE-KOTOBA.md).
- 실제 짧은 50ms WAV에서 이전 worker는 인코딩 없이 GPU 성공을 표시했고, 새 worker는 종료 22와 성공 표식 없음으로 거부했습니다. 정상 16초 공개 음성의 CUDA 요청 네 번은 실제 인코더 호출 1회를 각각 확인했습니다. 단위 검사와 실행 증거를 인식 품질 통과로 세지 않습니다.
- 구형 NPU 드라이버 `31.0.100.1688`의 전체 컴파일 1,818초 타임아웃은 과거 기록입니다. 이후 사용자가 공식 **`32.0.100.5540`을 수동 설치했으며 재부팅하지 않았습니다**. OpenVINO `2024.1`에서는 실제 `NPU.3720` 전체 컴파일 **355,621.030ms**, 첫 추론 **3,307.984ms**, 합성 비교 cosine **0.984372474598** / normalized RMSE **0.176712698545**를 관측했습니다. 별도 resident worker의 16초 음성 request 0은 전체 추론 **3,985.201ms**, 인코더 **3,380.651ms**, 원시 호출 **1회**로 완료됐지만 request 1은 `DEVICE_LOST` (`0x70000001`)와 종료 22로 실패했습니다. 이 SDK의 반복 실행 실패를 새 SDK 결과와 구분합니다.
- 이후 OpenVINO **`2026.4.1`**의 동일 원본/IR resident worker는 공개 일본어 16초 음성 요청 **네 번을 모두 실제 NPU로 완료**했습니다. 콜드 준비 **299,730.433ms**, 첫 추론 **4,177.404ms**, 후속 추론 **2,480.040/2,482.592/2,553.997ms**, 후속 벽시계 **2,484.615/2,486.966/2,558.898ms**이며 원시 호출은 각각 **1회**입니다. 네 SRT는 바이트가 같고 정규화한 인식문 128자는 기존 CUDA 표본과 일치했습니다. 해당 표본의 반복 실행·텍스트 일치이며 정답 대비 WER, 장시간 안정성, 10/60초 버퍼나 가사 전체 품질 통과를 뜻하지 않습니다. GPU 경로를 유지합니다.
- 정상 빌드 worker에서도 설치기가 만든 합성 16초 PCM **네 요청 모두 실제 NPU·원시 호출 1회**를 확인했습니다. 캐시 사용 준비 **9,797.446ms**, 첫 추론 **3,452.014ms**, 후속 추론 **2,052.547/2,055.236/2,060.860ms**, 후속 최대 벽시계 **2,064.406ms**였습니다. 공개 음성 4회와 합성 4회로 총 8회의 실제 NPU 실행을 확인했으며 합성 입력의 인식 정확도를 주장하지 않습니다.
- 이 근거로 앱 내부 ASR의 헤더·라이브러리·런타임 핀을 **OpenVINO `2026.4.1.22982`**로 갱신하고 정상 AI 빌드의 네이티브 CPU 검사 **7/7**을 통과했습니다. Whisper b5454와 CUDA가 없는 일반 CPU/Vulkan 빌드를 유지하며 번역 DLL 폴더는 분리합니다. NPU 플러그인·컴파일러·로더·VM과 SDK 원문 라이선스·재배포 목록을 함께 스테이징합니다. 최신 40+ INT8 TOPS 제품도 별도 PC 실측이 필요합니다. 장치가 보고한 FP16 5.7344 TFLOPS와 이상적 인코더 시간 396.51ms는 실측 처리량이나 제품 최소 사양이 아닙니다.
- 번역은 최신 자막 버퍼에서 대상 cue 전후 최대 60초의 문맥을 제공하고 대상 cue만 번역합니다. 최초 실제 Hy-MT2의 입력 JSON 되풀이 문제를 모델별 prompt·응답 처리로 수정했고 실제 CUDA의 직접 작성한 무문맥·문맥 입력 검사를 통과했습니다. 이 예제의 통과가 모든 가사·대화의 번역 품질을 보장하지는 않습니다.
- 캡처 허용은 개발자 모드 안에서만 제공하며 기본 캡처 방지는 켭니다. 개발자 모드 활성화와 캡처 방지 해제에는 **서로 별도의 책임 안내와 확인**을 요구합니다. 동의 대기 중 차단과 과거 미체크 설정의 우회 금지 회귀를 통과했습니다. 안내는 [GPLv3의 보증·책임 조항](../../LICENSE)과 적용 법률의 범위에서 설명하며 모든 책임에 대한 포괄 면책이나 법적 권리 포기를 뜻하지 않습니다. 최종 추출 패키지 검사는 대기 중입니다.
- 실제 로그의 `SwapChain Present failed`와 `0x887A0005` (`DXGI_ERROR_DEVICE_REMOVED`)로 영상 출력 장치 손실을 확인했습니다. [Microsoft의 DXGI 오류 정의](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-error)에 맞춰 해당 오류와 `0x887A0007` (`DEVICE_RESET`)을 세션당 한 번 감지하고, 제목·위치·일시정지 의도를 보존해 **한 번만 재생 출력을 다시 만드는 복구**를 통합했습니다. 여섯 소유 파일 조건과 실물 디스크 메뉴 동작 후 원위치·일시정지·가져온 자막 보존 회귀를 통과했습니다. 반복 손실의 무한 재시도와 오래된 오류의 새 소스 재열기도 차단했습니다. 장시간 재생과 다양한 복잡한 메뉴 경로 검증은 대기 중입니다.
- 이전 실물 시험에서 연결 Blu-ray의 시작 안내는 20,020ms까지 자연 진행한 뒤 약 31초 내 인터랙티브 메뉴에 진입했습니다. AI 설정은 켜진 채 유지했습니다. 이 관측은 새 복구 동작의 실물 검증과 구분합니다. 과거 AACS 설정 읽기 실패의 근본 원인은 미확정이며 키 파일 복원·복사는 하지 않았습니다.

candidate1은 ZIP 해시, 736개 파일 manifest, 모델·라이선스, 최소 PATH의 네이티브 의존성, 독립 추출본의 소유 WAV GPU ASR 검사를 통과했습니다. 이후 소스가 변경돼 **최종 candidate2의 ZIP·체크섬·독립 추출 실행·Windows/Linux CI·실제 설치 화면 검증은 별도로 필요**합니다. 패키지·CI 결과는 확인 후 추가합니다. 이전 버전의 태그·ZIP은 변경하지 않습니다. 보호 디스크의 키·인증서·영상·음성·메뉴 이미지·인식 자막은 공개 자료에 포함하지 않습니다.

## English

This is the **pre-packaging source/observation record**. Check the [versioned release](https://github.com/mk0000001/luma-player/releases/tag/v0.1.0-alpha.6) and its attached validation report for publication status, final ZIP hash and installed-package checks. Current source passed app CTest **21/21**, normal ASR native CPU tests **7/7**, encoder installer fixtures **25/25 under each PowerShell 7/5.1**, physical UI recovery/consent regressions **14/14**, translation unit **80/80** and service **27/27**. Actual CUDA tests with independently written raw/context inputs also passed. Candidate2 package/CI validation is pending.

- Implemented native Kotoba FP16 export, shared source/IR identity checks, raw per-request encoder timing/counts and separate NPU cache preparation. Qualification submits four actual requests for owned synthetic 16-second input, requires actual NPU execution and positive raw calls, and requires both complete inference and wall time to be at most 3,000ms for each of the three subsequent requests. Automatic NPU requires calibration matching source, IR, worker, runtime and driver; missing/failed calibration selects GPU. Advertised TOPS and architecture names do not select it. Legacy base models and explicit manual NPU override remain available. Final portable-installer profile and GUI 10/60-second coverage checks are pending. See [setup](../INSTALL-KOTOBA-NPU.md) and [performance](../PERFORMANCE-KOTOBA.md).
- Actual 50ms audio reproduced false GPU acknowledgement in the previous worker; the new worker rejects it with exit 22 and no success marker. Four normal 16-second public-audio CUDA requests each confirmed one real encode. Unit checks and execution evidence do not establish recognition quality.
- The 1,818-second full-compile timeout on NPU driver `31.0.100.1688` is historical. The user then **manually installed official driver `32.0.100.5540`, without rebooting**. With OpenVINO `2024.1`, actual `NPU.3720` compilation took **355,621.030ms**, first inference **3,307.984ms**; synthetic comparison observed cosine **0.984372474598** and normalized RMSE **0.176712698545**. A separate resident worker's 16-second request 0 completed in **3,985.201ms**, with **3,380.651ms** encoder time and **one** raw call. Request 1 failed with `DEVICE_LOST` (`0x70000001`) and exit 22. Distinguish that SDK's repeated-execution failure from the newer result.
- The same source/IR on an OpenVINO **`2026.4.1`** resident worker subsequently completed **all four genuine NPU requests** for a public 16-second Japanese sample. Cold readiness was **299,730.433ms**, first inference **4,177.404ms**, subsequent inference **2,480.040/2,482.592/2,553.997ms**, subsequent wall time **2,484.615/2,486.966/2,558.898ms**, with **one raw call each**. The four SRTs were byte-identical; normalized recognized text matched the existing CUDA sample at 128 characters. This is sample-specific execution/text agreement, not ground-truth WER, long-run stability, 10/60-second coverage or general lyrics quality. GPU remains available.
- The normal-build worker also completed **all four generated synthetic 16-second requests on actual NPU, one raw call each**: cached readiness **9,797.446ms**, first inference **3,452.014ms**, subsequent inference **2,052.547/2,055.236/2,060.860ms**, maximum subsequent wall time **2,064.406ms**. Four public-speech plus four synthetic requests establish eight actual NPU executions, not synthetic-input recognition accuracy.
- Based on this evidence, app-local ASR headers/libraries/runtime are pinned to **OpenVINO `2026.4.1.22982`**; the normal AI build passed **7/7 native CPU tests**. Whisper b5454 and the normal CUDA-free CPU/Vulkan build remain, with translation DLLs isolated. Staging includes NPU plugin/compiler/loader/VM DLLs plus original SDK notices and the redistributable list. Recent 40+ INT8 TOPS devices still require per-PC qualification. Reported FP16 capacity of 5.7344 TFLOPS and the ideal 396.51ms encoder calculation are not measured throughput or product minima.
- Translation uses up to 60 seconds of context on each side of the target cue from the latest caption buffer and translates only that cue. Model-specific prompt/response handling corrected the initial real Hy-MT2 JSON echo; actual CUDA raw/context tests with independently written inputs passed. These examples do not guarantee general lyrics/dialogue quality.
- Capture permission is restricted to developer mode; capture protection defaults on. **Separate responsibility notices and acknowledgements** are required for enabling developer mode and disabling capture protection. Regressions passed for blocking while consent is pending and preventing legacy unchecked settings from bypassing it. Notices remain within [GPLv3 warranty/liability terms](../../LICENSE) and applicable law; they do not grant blanket immunity or waive statutory rights. Final extracted-package checks remain pending.
- Actual `SwapChain Present failed` logs with `0x887A0005` (`DXGI_ERROR_DEVICE_REMOVED`) confirmed video-output device loss. Following [Microsoft's DXGI error definitions](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-error), detection of this error and `0x887A0007` (`DEVICE_RESET`) is limited to once per session. **One bounded output recreation** preserves title, position and pause intent. Six owned-file cases and physical-disc menu recovery preserving position/pause/imported captions passed. Repeated loss stops recovery, and stale errors cannot reopen a newer source. Long playback and diverse complex-menu validation remain pending.
- In an earlier physical test, the connected disc's First Play advanced to 20,020ms and reached its interactive menu in about 31 seconds with AI enabled. This does not validate the new recovery path. The original AACS failure's root cause remains unconfirmed; no key restoration or copying occurred.

Candidate1 passed ZIP hash, 736-file manifest, model/license, minimal-PATH native dependency and owned-WAV GPU ASR checks from an independent extraction. Source changed afterward, so **final candidate2 ZIP/checksum, extraction execution, Windows/Linux CI and installed-UI checks require separate validation**. Package/CI outcomes will be added after verification. Earlier tags and archives remain unchanged. Protected-disc keys, certificates, media, menu images and recognized transcripts are excluded from public artifacts.
