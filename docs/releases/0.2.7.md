# LumaPlayer 0.2.7

## 한국어

### Android에서 재생 시작

Windows에서 LumaPlayer를 켜면 같은 Wi-Fi의 Android 앱에 PC가 자동으로 나타납니다. Android의 PC 목록은 열린 동안 자동으로 갱신되며, Windows는 앱을 실행한 뒤 네트워크에 연결해도 검색 응답을 시작합니다.

Windows에서 영상이나 Blu-ray 본편을 열고 **내부망 재생 → 연결된 기기에서 현재 미디어 재생 시작 허용**을 켜세요. 페어링한 Android 기기에서 **재생 시작**을 누르면 그 영상이 재생됩니다. PC가 소스나 타이틀을 바꾸거나 공유를 중지하거나 기기 연결을 해제하면 권한을 다시 켜야 합니다. [내부망 재생 안내](../LAN-PLAYBACK.md)

### 보안 보완

- 로컬 번역기는 실행마다 새 인증서와 토큰을 발급받습니다. 플레이어는 인증서가 일치하는 로컬 HTTPS 연결에서만 자막과 번역 문맥을 보냅니다.
- LAN 호스트의 연결 한도와 Android가 받는 미디어 유형 검증을 강화했습니다. Wi-Fi Direct가 주소를 얻지 못하면 일반 내부망 연결로 돌아갑니다.
- Windows 자막 프로젝트의 로컬 경로와 읽기 크기를 검사합니다. 인앱 업데이트는 기존 설치 경로의 실행 파일이 확인된 경우에만 적용합니다.

### 검증

- Windows 11에 기본 설치본을 설치해 34초 합성 H.264 영상이 끝까지 재생되는 것을 확인했습니다. 같은 PC에서 CPU와 RTX 4080 Laptop GPU의 CUDA로 합성 자막을 번역했습니다.
- 갤럭시 탭 `SM-X736N`에 0.2.7 APK를 설치했습니다. Wi-Fi 자동 검색과 6자리 페어링을 확인했고, PC에서 시작을 허용하기 전에는 요청이 거절됐습니다. 허용 후 갤탭의 **PC 미디어 재생 시작**으로 송출을 시작해 합성 영상 34초를 끝까지 재생했습니다. Android 화면 합성 기록에서 20초 이후에도 영상 프레임이 표시됐습니다.
- Windows 자동 테스트 28개와 격리 Android 단위 테스트 26개가 통과했습니다. Android APK 서명을 확인했습니다.
- 갤탭의 PC 목록을 열어 둔 상태에서 Windows LumaPlayer만 시작했을 때 약 6초 안에 PC가 나타났습니다. 두 기기에서 검색이나 주소 적용 버튼을 누르지 않았습니다.
- LAN 호스트의 승인·취소·연결 한도를 격리 테스트했습니다. Windows 계정 간 격리와 네이티브 미디어 구성요소의 전체 감사는 추가 검증이 필요합니다.
- Windows에 포함된 Qt 6.11.3의 HTTP 응답 처리에는 공급사 보안 패치가 남아 있습니다. 번역 요청은 인증서를 확인한 로컬 실행기와 HTTP/1.1로만 통신합니다. [Qt 보안 공지](https://www.qt.io/blog/security-issue-cve-2026-116337)

소스 빌드에는 Go 1.26.11 이상이 필요합니다. 공식 설치본은 보조 실행기를 포함합니다.

## English

### Start playback from Android

Open LumaPlayer on Windows and the PC appears automatically in the Android app on the same Wi-Fi network. Android refreshes the PC list while it is open. Windows starts responding even if it joins the network after the app opens.

Open a video or the main Blu-ray title on Windows and enable **Allow connected devices to start the current media** in the LAN playback panel. Tap **Start playback** on a paired Android device to play the media. Enable the permission again after the PC changes the source or title, stops sharing, or disconnects a device. [LAN playback guide](../LAN-PLAYBACK.md)

### Security hardening

- The local translation worker receives a new certificate and token on each launch. The player sends caption text and context only over the local HTTPS connection with the matching certificate.
- The LAN host limits connections, and Android validates the received media type. Wi-Fi Direct falls back to regular LAN when it cannot obtain an address.
- Caption projects on Windows are checked for local paths and bounded reads. In-app updates require the expected executable to be present in the selected installation directory.

### Verification

- On Windows 11, the standard installer was used to install the app, which played a 34-second synthetic H.264 clip to completion. The same PC translated synthetic captions with the CPU and with CUDA on an RTX 4080 Laptop GPU.
- The 0.2.7 APK was installed on a physical Galaxy Tab `SM-X736N`. Wi-Fi discovery and six-digit pairing worked. The tablet request was denied until the PC enabled remote start. After enabling it, the tablet started sharing and played the 34-second clip to completion. Android compositor records showed video frames presented beyond 20 seconds.
- All 28 Windows test suites and 26 isolated Android unit tests passed. The Android APK signature was verified.
- With the Galaxy Tab already on the PC list, launching LumaPlayer on Windows made the PC appear within about six seconds without touching either device’s discovery controls.
- Isolated LAN host tests covered authorization, revocation, and connection limits. Cross-account Windows isolation and a complete audit of native media components require further validation.
- The bundled Windows Qt 6.11.3 still needs the vendor's HTTP response patch. Translation requests use HTTP/1.1 with the certificate-verified local worker. [Qt security advisory](https://www.qt.io/blog/security-issue-cve-2026-116337)

Building from source requires Go 1.26.11 or newer. Official installers bundle the helper.
