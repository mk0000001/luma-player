# LumaPlayer 0.2.0-beta.2

## 한국어

한 PC에서 읽는 Blu-ray와 준비한 자막을 같은 네트워크의 Android나 Windows PC에서 재생할 수 있습니다. Windows의 **내부망 재생**에는 연결 중인 기기와 기억한 기기가 표시됩니다. 다른 Windows PC에서는 **PC에서 받기**를 열어 검색하거나 사설 IP를 직접 입력하세요. 양쪽의 6자리 코드를 확인하고 송출 PC에서 승인하면 연결됩니다. [내부망 재생 안내](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/LAN-PLAYBACK.md)

Windows 앱은 실행 시 공식 GitHub 릴리스를 확인합니다. 설정에서 업데이트를 수동 확인하거나 실행 시 알림을 끌 수 있습니다. 설치를 선택하면 앱이 서명된 릴리스 정보와 설치 파일의 SHA-256을 확인합니다. [업데이트 안내](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/UPDATES.md)

Windows x64 설치 파일에는 CUDA 라이브러리와 기본 Turbo 인식 모델이 들어 있습니다. 권장 설치에서 full-v3 Q5 인식과 Hy-MT2 번역 모델을 내려받습니다. Android APK는 Android 9 이상을 대상으로 합니다. [Windows 설치 안내](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/WINDOWS-INSTALLER.md)

테스트 PC는 Core Ultra 9 185H, 32 GB RAM, RTX 4080 Laptop GPU 12 GB와 PIONEER BDCTD03RS를 사용합니다. 1080p 재생과 준비된 자막 기준 추정 최소는 4코어 CPU, 8 GB RAM, H.264 하드웨어 디코딩입니다. 실시간 인식과 번역을 함께 쓰려면 테스트 PC 수준을 권장합니다. 권장 사양에 못 미치면 자막을 먼저 만들어 사용하세요. [측정 근거](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/testing/2026-11-12-beta5-performance-security.md) · [자막 준비 안내](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/PREPARE-CAPTIONS.md)

### 검증 결과

- 같은 Windows PC에서 두 플레이어를 열어 실제 Wi-Fi 인터페이스의 자동 검색, 6자리 코드 대조와 승인, 로컬 동영상과 자막 표시, 재생 위치 이동, 기기 연결 해제를 확인했습니다.
- 츠키 무도관 Blu-ray로 Windows의 준비된 자막과 내부망 송출을 확인했습니다. Android 16 에뮬레이터에서 사설 IP로 연결해 AVC 영상과 원본 LPCM 음성 재생을 확인했습니다. 별도 합성 영상으로 기억한 기기의 재연결과 캡처 시 영상만 가려지는 동작도 확인했습니다. 별도 Windows PC와 Android 실기기, 모바일 HDR·Dolby Vision·Atmos 출력은 검증 범위에 포함되지 않았습니다.
- Windows 자동 검사 28개와 로컬 인식 엔진 검사 9개가 통과했습니다. LAN 서비스는 Go 경쟁 상태 검사와 `go vet`를 통과했습니다. 업데이트는 서명·해시·주소·버전 검사를 거치며, 설치 대상이 확인 후 바뀌면 설치를 중단하는 동작도 확인했습니다.
- 공개 GitHub 통신에는 Windows WinHTTP를 사용합니다. LAN 수신 영상은 인증된 스트림과 같은 PC의 전용 재생 연결을 통해 열립니다. 보호된 디스크의 키, 미디어와 생성 자막은 배포 파일에서 제외했습니다. [Qt 네트워크 보안 공지](https://www.qt.io/blog/security-issue-cve-2026-116337)

## English

Play a Blu-ray and prepared captions from one PC on Android or another Windows PC on the same network. Windows shows connected and remembered devices under **내부망 재생**. On the receiving PC, open **PC에서 받기** to search for a host or enter its private IP. Confirm the six-digit code on both screens and approve on the host PC. [LAN playback guide](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/LAN-PLAYBACK.md)

The Windows app checks the official GitHub releases at launch. Check manually in Settings or turn off startup notifications. When you choose to install, the app verifies the signed release metadata and the installer SHA-256. [Update guide](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/UPDATES.md)

The Windows x64 installer includes CUDA libraries and the default Turbo recognition model. Recommended setup downloads full-v3 Q5 recognition and Hy-MT2 translation. The APK targets Android 9 and later. [Windows installation guide](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/WINDOWS-INSTALLER.md)

The test PC has a Core Ultra 9 185H, 32 GB of RAM, an RTX 4080 Laptop GPU with 12 GB VRAM, and a PIONEER BDCTD03RS drive. The estimated minimum for 1080p playback with prepared captions is a four-core CPU, 8 GB of RAM, and H.264 hardware decoding. Use a system similar to the test PC for simultaneous live recognition and translation. On lower-spec PCs, prepare captions before playback. [Measurements](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/testing/2026-11-12-beta5-performance-security.md) · [Caption preparation](https://github.com/mk0000001/luma-player/blob/v0.2.0-beta.2/docs/PREPARE-CAPTIONS.md)

### Verification

- Two players on one Windows PC verified automatic discovery on the Wi-Fi interface, six-digit code comparison and approval, local video with captions, seeking, and device disconnect.
- The TUKI Budokan Blu-ray verified prepared captions and LAN streaming on Windows. An Android 16 emulator connected by private IP and played AVC video with original LPCM audio. A separate synthetic video verified remembered-device reconnect and video-only capture masking. Separate Windows PCs, a physical Android phone, and mobile HDR, Dolby Vision, and Atmos output remain unverified.
- All 28 Windows test suites and 9 local recognition-engine checks passed. The Go LAN service passed race checking and `go vet`. Update checks covered signature, checksum, URL, and version validation. The installer refused to overwrite a target that changed after verification.
- Public GitHub requests use Windows WinHTTP. LAN playback receives authenticated media through a private on-device connection. Protected-disc keys, media, and generated captions are excluded from release assets. [Qt Network advisory](https://www.qt.io/blog/security-issue-cve-2026-116337)
