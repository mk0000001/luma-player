# 0.1.0-alpha.8 — 재생 전 전체 자막 / Full captions before playback

## 한국어

**후속 확인한 알려진 문제:** 가장 긴 사전 생성 타이틀과 메뉴 ALL PLAY가 다른 실물 디스크에서는 완성 프로젝트를 해당 본편에 연결하지 못합니다. 다른 타이틀에 자막을 강제로 적용하지는 않습니다. [alpha.9](0.1.0-alpha.9.md)에서 준비 타이틀 직접 선택과 모드별 이어보기·출력 복구를 수정했습니다. alpha.8 태그·바이너리는 이 문제를 포함한 상태로 보존합니다.

**AI 자막 → 재생 전 전체 자막 만들기**를 추가했습니다. 파일이나 연결된 Blu-ray의 선택 타이틀 전체를 영상 재생 없이 원문 인식한 뒤, 인식한 텍스트와 앞뒤 원문 문맥으로 한국어를 번역합니다. 취소·중간 저장·동일 조건 이어하기, 원문·한국어·선택 독음 조합 SRT와 다시 열 수 있는 프로젝트를 제공합니다. [사용 안내](../PREPARE-CAPTIONS.md).

완성 프로젝트는 탐색 후 실시간 AI 준비를 기다리지 않습니다. 미디어·길이·Blu-ray 플레이리스트·오디오가 맞을 때만 적용하고, 다른 음성으로 바꾸면 기존 자막을 유지하지 않습니다. 생성 창의 입력을 바꾸면 이전 완료 결과의 재생 버튼을 비활성화합니다. AI가 이미 켜진 상태에서 외부 자막 가져오기에 실패해도 오래된 외부 자막을 제거하고 자동 인식으로 전환합니다.

Blu-ray 사전 생성은 실시간 읽기 제한을 적용하지 않으며 감상 중의 기존 10초/60초 자막 정책은 유지합니다. 사전 생성 창 같은 모달 대화상자를 여는 동안 독립 재생바가 버튼을 덮지 않도록 숨기고, 닫으면 복원합니다.

### 확인한 범위

- Windows 전체 Qt 검사 **27/27**, **221.40초** 통과. 원문 전체 완료 후 번역, 80개 번역의 큐 제한 처리, 취소·중간 저장·재개, 입력 변경 거부, 모델 없는 완성 프로젝트 열기, 손상 파일·캐시·늦은 응답, 오디오·타이틀 일치 등을 검사했습니다.
- 전체 검사 뒤 발견한 모달 재생바 겹침은 창/전체화면 두 회귀 사례의 실패를 먼저 확인했습니다. 수정 후 실제 Windows Qt **4/4**, 영향받은 대화상자·UI·재생바 검사 **3/3, 74.98초**가 통과했습니다.
- 직접 만든 24초 영상과 공개 일본어 시험 음성으로 **영상 재생 없는 전체 생성 16.817초**, 원문 2구간·한국어 6페이지·번역 건너뜀 0개를 확인했습니다. full large-v3 Q5와 Hy-MT2 CUDA를 사용했습니다. 실제 UI에서 완성 프로젝트의 탐색·챕터 이동이 AI 버퍼에 갇히지 않는 경로도 검사했습니다.
- 실물 Blu-ray의 짧은 **전체 플레이리스트 20,020ms** 준비가 6.997초에 완료됐습니다. 이 타이틀은 음성이 없어 원문·번역 0개였습니다. 이 결과만으로 104분 본편 생성 완료를 주장하지 않습니다. 별도의 본편 전체 생성과 최종 포터블 실행 관찰은 GitHub Release의 `validation-runtime.json`에 기록합니다.

최종 ZIP의 크기·SHA-256·고정 실행기·원문 라이선스·깨끗한 소스 커밋·독립 추출 검증은 `validation-package.json`과 릴리스 본문에서 확인합니다. CUDA ASR/번역 실행기와 기본 Turbo 모델을 포함하며, 선택 full/Kotoba ASR 및 번역 가중치는 별도입니다. 기존 alpha.7 이하 태그와 파일을 교체하지 않습니다.

현재 GitHub Actions의 Windows/Linux 작업은 실행 인프라 제한으로 검사 단계를 시작하지 못했습니다. 로컬 Windows 결과와 CI 통과를 구분하며, 새 Linux 실행·하드웨어 검증을 통과로 표시하지 않습니다. 기존 DRM/HDCP·HDR/Dolby Vision·음원 출력의 확인 한계는 유지합니다.

노래 인식·번역 의미·말투·시간 정렬에는 오류가 남을 수 있습니다. 사전 생성은 미래 원문이 준비되는 시점을 앞당기며 모델 자체의 정확성을 보장하지 않습니다. 보호 디스크 키·인증서·미디어·메뉴 이미지·인식한 상용 자막과 개인 경로는 공개 자료에서 제외합니다.

## English

**Known issue discovered afterward:** on the observed disc, the longest prepared title differs from menu ALL PLAY and the completed project cannot attach to its intended feature. Mismatched captions are not forced. Alpha.9 fixes explicit prepared-title selection, mode-aware resume and output recovery. The alpha.8 tag/binaries retain this issue unchanged.

Added **AI 자막 → 재생 전 전체 자막 만들기** for complete files and selected connected Blu-ray titles without video playback. All original recognition finishes before recognized-text/context Korean translation. Progress, cancellation, checkpoints, compatible resume, original/Korean/display SRT and reusable projects are supported. See the linked guide.

Completed projects bypass live ASR holds after seeking and validate source, duration, playlist and audio before attachment. Changing audio detaches incompatible captions. Changing preparation inputs invalidates the previous result's play action. Invalid external-subtitle imports now clear stale cues and restart automatic recognition even when AI was already checked.

Only offline Blu-ray generation omits the live reader's rate limit; live ten/sixty-second behavior remains. The transport hides behind modal dialogs and restores afterward, preventing covered preparation buttons.

Windows Qt **27/27** tests passed in **221.40 seconds**, including complete-original-before-translation ordering, 80-cue bounded queue handling, cancellation/resume, incompatible-input rejection, loading without models, corrupt/stale state and audio/title binding. The later modal-overlap regression was reproduced in windowed/fullscreen cases, then passed **4/4** on actual Windows Qt and **3/3 affected suites in 74.98 seconds** after correction.

An independently authored 24-second video/public Japanese speech fixture completed headless preparation in **16.817 seconds**, with two original cues, six Korean pages and no skipped translations, using full large-v3 Q5 and Hy-MT2 CUDA. Native UI checks cover seek/chapter behavior without live-buffer holds. A complete **20,020 ms** physical-disc playlist completed in 6.997 seconds but contained no speech; that alone does not verify the 104-minute feature. Separate full-feature generation and extracted-portable observations are recorded in `validation-runtime.json`.

Check `validation-package.json` and the release body for final archive size/SHA-256, pinned runtimes, raw licenses, clean source commit and independent extraction. CUDA ASR/translation runtimes and default Turbo are included; optional full/Kotoba and translation weights remain separate. Earlier alpha.7 and older assets remain immutable.

GitHub Windows/Linux Actions currently cannot begin test steps because of execution-infrastructure restrictions. Local Windows checks are distinct from CI; new Linux runtime/hardware validation remains unverified. Existing DRM/HDCP, HDR/Dolby Vision and audio-output limitations remain. Pre-generation improves context availability, not guaranteed singing recognition, translation tone/meaning or synchronization. Protected keys, certificates, media, menus, commercial transcripts and private paths are excluded from public artifacts.
