# 구현 결정과 비용

사용자는 기술 선택과 실행을 위임했습니다. 다음은 구현자가 정한 내용입니다.

- **C++20 / Qt 6**: Windows/Linux의 네이티브 재생 엔진과 창을 직접 연결하기 위해 선택했습니다. Rust보다 C++ 수명·스레드 처리를 더 주의 깊게 검토해야 합니다.
- **검증 가능한 프리뷰**: 배포 버전은 구현 범위와 실패·미검증 항목을 공개합니다. 초기 설계는 디스크가 실패해도 실패를 명시한 개발 프리뷰를 허용했지만, 이번 배포의 츠키 메뉴·본편 기준은 실제로 통과했습니다. 프리뷰 자체가 팟플레이어 전체 기능의 완료를 뜻하지 않습니다.
- **서로 다른 미디어 엔진**: 디스크 메뉴는 libVLC, 일반 파일의 GPU 재생은 libmpv로 담당합니다. 엔진 두 개의 의존성과 상태·입력을 관리하는 비용이 있습니다.
- **정확한 플레이리스트의 AI 음성**: FFmpeg full의 libbluray 경로로 현재 MPLS와 오디오 PID를 지정합니다. 더 큰 도구 바이너리가 필요하며, 재생 길이로 플레이리스트를 하나로 식별할 수 없는 타이틀은 AI가 잘못된 음성을 인식하지 않도록 거절합니다.
- **종료 중 창 메시지 처리**: libVLC의 동기 stop을 작업 스레드에서 실행하고 GUI 이벤트를 처리합니다. 네이티브 창 종료의 교착을 피하며, 중지 중 입력·타이머·자막 작업의 재진입을 제어해야 합니다.
- **검증을 구분한 지원 표시**: 인증 Dolby Vision 출력, 모든 DRM, Linux 실물 동작, 한국어 번역과 팟플레이어 전체 기능을 완료로 표시하지 않습니다. 요청한 장기 범위는 [이슈 목록](https://github.com/mk0000001/luma-player/issues)에서 계속 추적합니다.

남겨 둔 작은 제한은 [VLC 생성 자막 트랙의 누적](https://github.com/mk0000001/luma-player/issues/6)입니다. 파일용 mpv에서는 관리 트랙을 교체하며, VLC에서는 긴 세션에서 선택 목록이 늘어날 수 있습니다.
